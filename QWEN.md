# AH Sniper — архитектура и правила изменений

Репозиторий хранит очищенные исходники. Адреса инфраструктуры, ключи, идентификаторы туннеля, аккаунты и рабочие данные задаются локально. Этот документ вместе с `AGENTS.md` определяет границы сборки и безопасного обновления.

## Архитектура

- `desktop/main.py`: PyWebView, Flask на `127.0.0.1:8765`, коллектор, RAM-кэш, SQLite, push в Supabase, веб-авторизация.
- `desktop/ahgem.py`: OAuth Blizzard, EU/US, HTTP/2, обработка аукционных лотов.
- `desktop/browser.py`: каталог, метаданные и иконки предметов.
- `desktop/topx_cache.py`, `desktop/ws_server.py`: средние цены и standalone WebSocket на 8766.
- `static/index.html` и общие модули: таблицы, карточка, фильтры и пресеты для EXE и веба.
- `static/landing.html`: публичный лендинг.
- Supabase хранит снимки аукциона, веб-аккаунты, лицензии и активации. Веб-клиент читает снимки напрямую с публичным ключом и проверяет `updated_at` каждые 15 секунд.
- Cloudflare Tunnel публикует админский Flask-сервер; `start_all.bat` запускает туннель через HTTP/2 и проверяет существующие процессы перед запуском.

Пути к локальным данным разрешает `paths.py`: из исходников — корень проекта, в EXE — папка рядом с исполняемым файлом. Статические ресурсы входят в EXE.

## Конфигурация

- `.env`: Blizzard API, регион, `PUBLIC_ORIGIN`, `SUPPORT_URL`, `SUPPORT_LABEL`, необязательная аналитика. Только локальный ADMIN-контекст; USER-сборка не включает этот файл.
- `supabase_config.json`: админский `supabase_url`, `anon_key`, `service_key`. Не включается в EXE и пользовательский релиз.
- `public_config.json`: только `supabase_url` и `anon_key` для пользовательской лицензии. Переменные `SUPABASE_URL` и `SUPABASE_ANON_KEY` имеют приоритет; админский конфиг для этой задачи не читается.
- `tunnel_token.txt`: локальный токен своего туннеля. Не помещать токен в bat или Git.
- Необязательный `tunnel_interface.txt` хранит GUID физического адаптера. `tools/tunnel_bind_address.ps1` определяет его текущий IPv4 при каждом запуске. Явный `TUNNEL_EDGE_BIND_ADDRESS` имеет приоритет; системные маршруты и VPN не меняются.
- `settings.json`, `collector_settings.json`, `license.json`, `presets.json` и `.flask_secret` относятся к конкретной установке и исключены из Git.

Не записывать действующие домены, адрес проекта Supabase, контакты, пароли, ключи или ID аналитики в исходники и документацию. В примерах допустимы только пустые значения и зарезервированные имена `example.invalid`.

## ADMIN и USER

`build_exe.py` формирует `_build_flags.py`; при запуске из исходников без файла флага режим ADMIN включён по умолчанию. Тесты используют `AH_BUILD_FLAGS` во временном каталоге.

- `python build_exe.py`: `AuctionMonitorAdmin.exe`, push, веб-авторизация, локальная `.env` может быть встроена в сборку. Только для машины владельца; не публиковать.
- `python build_exe.py --user`: `AuctionMonitor.exe`, без push, веб-авторизации и встроенной `.env`; обфускация PyArmor.
- Локальный ADMIN-коллектор не зависит от доступности лицензионного API. USER сохраняет PRO/HWID-проверку, веб — авторизацию аккаунта.
- `python tools/prepare_release.py`: только USER EXE, проверенная публичная конфигурация лицензии, справочники, очищенная БД, иконки, инструкция и информация о сборке. Привилегированные ключи в публичной конфигурации запрещены.
- В пользовательской БД с данными остаются только `realms`, `items`, `item_meta`; рабочие таблицы истории создаются пустыми. Аккаунты и история админа не копируются.

Не использовать `--optimize 2` в PyInstaller: это ломает PyWebView. Следить за trial-ограничениями PyArmor, не считать обфускацию гарантией недоступности исходников.

## Веб и индексация

`PUBLIC_ORIGIN` определяет публичный HTTPS-хост и его www-вариант. Разрешены только эти хосты и localhost; чужой Host получает 403.

- `/`: лендинг на публичном хосте, интерфейс на localhost.
- `/app`: приложение; `/login`, `/register`, `/profile`: авторизация и аккаунт.
- `/landing`: локальный предпросмотр, 301 на `/` на публичном хосте.
- `/robots.txt`, `/sitemap.xml`, `/site.webmanifest`: публичные служебные маршруты. Sitemap содержит только лендинг.
- `/api/landing/deals` и `/browser/icon/<id>`: публичные данные для лендинга. Доступ без входа не означает разрешение индексировать все API.
- App/auth/API/browser получают `X-Robots-Tag: noindex`. Не добавлять закрытые маршруты, пользовательские фильтры и динамические таблицы в sitemap.
- Canonical, Open Graph, structured data, sitemap и проверка хоста аналитики используют конфигурацию. `GA_MEASUREMENT_ID` и `YANDEX_METRIKA_ID` читаются только из окружения.
- Auth, приложение и пресеты не кэшируются. ID Метрики хранится в `ymId`; события вызывает `window.ym`. Ошибка аналитики не мешает переходу после входа.
- Секретные пути возвращают 404. USER EXE не обслуживает публичные web-host маршруты. Не вызывать локальную `license_manager.activate_key()` из веб-активации.

## BoE и снайпинг

Цена, вторичные статы, сокет и дополнительный эффект относятся к одному текущему лоту. Декодировать `item.modifiers` и `bonus_lists`; не угадывать характеристики по item ID, ilvl, цене или старым наблюдениям.

Вторичные статы: modifiers 29/30, значения 32=Crit, 36=Haste, 40=Versatility, 49=Mastery. Для известных семейств 12.1 bonus 13695/13668 означает сокет, 13696/13662 без положительного socket bonus — отсутствие сокета. Неизвестное семейство оставляет сокет неизвестным. Эффекты 40=Avoidance, 41=Leech, 42=Speed, 43=Indestructible.

`ilvl_map.json` и `compute_ilvl()` определяют ilvl по bonus_lists; справочник обновляется при патчах. Avg остаётся исторической средней предмета/ilvl, а не выбранной комбинации статов.

- `Snipe items` и `BoE Snipe` независимы. Основной блок требует `items_enabled` и явного совпадения ID; пустой список никогда не выбирает все предметы.
- Оба режима включены — объединение совпадений; оба выключены — пустой снайпер. Выключение не очищает сохранённые поля. Старые пресеты без `items_enabled` считаются включёнными.
- BoE-фильтры независимы от основного блока; tertiary selector хранится отдельно как `effect`. Неизвестные метаданные не проходят условие «без сокета/эффекта».
- Снайпер, каталог и карточка одинаково фильтруют варианты и показывают соответствующую цену. Клик по цене открывает вариант с теми же ID/ilvl/статами/сокетом/эффектом.
- Каталог не ограничивается правилом пустого списка ID снайпера; picker возвращает один результат на ID с поиском и пагинацией.

## Пресеты и восстановление облака

Общие модули: `workspace.css`, `workspace.js`, `market-grid.js`, `item-detail.js`, `presets.js`, `preset-store.js`, `boe.js`.

Черновики сохраняются при вводе, разделяются по аккаунту или локальной установке и ID пресета. Записи идут последовательно; старый ответ не удаляет более новую правку. Черновик удаляется только после подтверждённого сохранения. Неудачное чтение облака не заменяет список пустыми значениями.

Создание, переименование и редактирование используют общую очередь. `client_id` внутри JSON предотвращает повторное создание после сбоя; временный `draft:` ID заменяется подтверждённым серверным ID. Редактирование другого пресета не копирует фильтры активного. Истечение тарифа не уничтожает сохранённые поля BoE. Экспорт включает черновики.

BoE-варианты используют `auction_data.items_json`, пресеты — `web_users.presets`; текущая реализация не требует SQL-миграции. После отказа Supabase коллектор повторяет небольшую проверку раз в 60 секунд и публикует полный актуальный снимок после восстановления. Во время сбора частичный снимок не публикуется.

Для UI-проверки создавать отдельный временный пресет. После проверки удалить только его и сравнить исходные пресеты с сохранённым снимком. Не менять пользовательский пресет ради теста. Офлайн-тесты не заменяют проверку записи в настоящее облако.

## Проверки и выпуск

Перед коммитом обязательны:

```text
python tests/test_build_gates.py
python -m py_compile desktop/main.py desktop/ahgem.py
python tools/check_repo_safety.py
git diff --check
```

Для BoE или пресетов также обязательны:

```text
python tests/test_boe_variants.py
node tests/test_boe_web.js
python tests/test_preset_persistence.py
node tests/test_preset_store.js
```

Для входа: `python tests/test_web_auth.py` и `node tests/test_web_auth.js`. Для локальной конфигурации: `python tests/test_deployment_config.py`. Полный каталог проверяется отдельно: `python tests/validate_items.py --full` на заполненной тестовой установке.

Исходники хранятся в публичном репозитории без реальных адресов инфраструктуры, секретов и рабочих данных. Пакеты пользовательских EXE не содержат исходников, ADMIN EXE, `.env`, привилегированной конфигурации, токенов или настроек владельца. Push не является деплоем. Пересборка действующей ADMIN EXE и перезапуск туннеля разрешены только после отдельного явного согласия владельца.

Не удалять резервные копии исходной установки. Не заменять чужие изменённые файлы и не проверять публикацию запуском production-сервисов.
